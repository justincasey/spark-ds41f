1. Direct exchange on a switched fabric port

  • What: at four ranks, the rank-order reduce-scatter's chunk exchange and PyNCCL's all_to_all_rows relay half of the opposite rank's block through a neighbour, because a cable ring has no link between ranks two apart. Behind a switch every pair is one hop, so the patch exchanges directly when sparknet renders SPARKNET_ROCE_TOPOLOGY=direct. Any other topology keeps the relay.
  • Evidence: prefill +2.7% at 32K, 128K and 256K; closed-loop decode unchanged; engine grid +0.46% ±1.05% over boots (no detectable change); greedy outputs and all top-20 logprob distributions identical over 16,384 positions.
  • Ready to port: experiments/2026-11-01-direct-exchange-switched/vllm-candidate-29/0640-…patch is the same change rebased on upstream's candidate-29 series. Checked by applying candidate-29's 71 patches and then this one: one docstring conflict, resolved; code applies unchanged and compiles.
  • Still open: build and measure it on candidate-29 (only measured on 1030); switch drop and HCA error counters were not read this session.

2. sparknet's switched NCCL profile port

tp4-switched inherits tp4-ring's NCCL settings. sparknet's own switched recipe differs in four values:

  • Evidence: taking it off the best stack costs 1.1% prefill (both boot pairs within 0.25%). Decode unchanged. 16 channels add nothing beyond noise.
  • How: an environment block on the tp4-switched shape (shapes may set environment). Do not add NCCL_MIN_NCHANNELS: the tooling rejects it on switched transports.

3. Drafter NVFP4 vocabulary head port, scope decision

  • What: VLLM_DS41_DRAFT_NVFP4_HEAD=1 gives the DSpark drafter its own NVFP4 vocabulary head instead of sharing the target's. Only draft quality depends on it; target outputs stayed identical.
  • Evidence: engine step 3.5–4.2% cheaper on every boot with it; removing it from the best stack puts the step back at stock and decode gains nothing.
  • Drop the rest of the old item: six drafts lost 0.6% to five, seven lost 1.2%, and the NVFP4 Markov head (VLLM_DS41_MARKOV_NVFP4) has no measurable effect.
  • Decision: put it on tp4-switched only, or recipe-wide after measuring tp4-ring and tp3-triangle.

4. Adaptive verification row cost 0.01 port, scope decision

  • Evidence: decode +0.7% (1 stream +1.15%) when added at six drafts. At five drafts it is the best of 0.005, 0.01 and 0.02 (each neighbour loses about 0.8%, one boot each).
  • Catch: a shape may set environment and sizing, not serve_args. The 0.035 is a literal inside the shared --speculative-config, so changing it changes every shape. Either measure it on ring and TP3 first, or add a placeholder a shape can set.
  • Not separately proven: the gain was measured with the NVFP4 head on; without the head, decode is about stock.

6–7. Method and tooling optional

  • Stock-overlay A/B: the stock arm mounted 1030's two Python files over the direct-exchange image, so both arms ran one image and no second build was needed. Works for any Python-only vLLM change.
  • Suites: suite.json (about 21 minutes a boot: outputs, grid, c16, c1, prefill 32K–256K) and stall-suite.json (stall-3, stall-11, cold 1M).
  • Lab publish guard: lab.py window open requires the commit on origin/main, while cluster sync already honours deployment.branch. A fork deploying another branch cannot open a window; following deployment.branch would fix it. Not written yet.
  • Do not port as-is: harness.py and measure.sh take the window without the publish guard and hard-code this site's addresses.
